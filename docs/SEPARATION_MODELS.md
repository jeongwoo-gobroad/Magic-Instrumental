# 3.0.0 분리 모델 선정과 동작

확인 기준: **2026-11-25 (한국 시간)**. 공개된 성능 비교, 실제 다운로드할 수 있는 가중치, 고정한 실행 도구의 호환성을 함께 확인했습니다. 결과는 아래 조건에서의 선정 근거이며 모든 곡에 대한 최고 음질을 보장하지 않습니다.

## 기본 선택

**자동 추천은 보컬에 BS-RoFormer Leap Xe, 기타·드럼·베이스·피아노에 BS-RoFormer SW 6파트, 키보드·신시사이저에 MVSep Mega 53 v1을 사용합니다.** 기존 HyperACE v2·deux도 남겨 이전 결과와 비교하거나 캐시를 재사용할 수 있습니다. 체크한 여러 음원을 함께 준비할 때 필요한 추천 모델을 각각 한 번 실행하고 결과를 공유합니다. 원곡 선택에는 AI 모델을 실행하지 않습니다.

SDR은 정답 음원과 비교한 분리 오차 지표이며 보통 높을수록 좋습니다. **서로 다른 평가 데이터의 수치를 합쳐 순위를 만들지 않았습니다.** 특히 기타 수치는 별도 기타 평가이며 Multisong 보컬 수치와 직접 비교할 수 없습니다. 네 파트 모델의 `other`에는 기타 외의 악기가 섞이므로 이를 ‘기타’로 표시하지 않습니다.

출처: [Leap Xe의 정확한 파일 평가](https://mvsep.com/quality_checker/entry/10846), [SW의 평가와 데이터 구분](https://www.mvsep.com/news/64), [기타 모델 비교](https://mvsep.com/algorithms/17), [SubRoformer 공식 릴리스](https://github.com/ZFTurbo/Music-Source-Separation-Training/releases/tag/v1.0.23), [Mega 53 공식 릴리스와 요구 조건](https://github.com/ZFTurbo/Music-Source-Separation-Training/releases/tag/v1.0.21), [Mega 공개 모델과 서비스 전용 모델의 파트별 비교](https://mvsep.com/algorithms/135).

**키보드와 피아노를 구분합니다.** Mega의 `keys`는 피아노·오르간·전기피아노·하프시코드 등 건반 계열을 묶은 출력입니다. SW의 `piano`는 피아노 출력입니다. Mega의 `synth`는 전자 합성음 범주여서 신스 베이스·패드·전자 타악기 등을 포함할 수 있습니다. 키보드를 연주하는 사람 한 명의 모든 소리를 정확히 묶어 분리하는 기능은 아닙니다. 신시사이저 점수는 특히 낮으므로 실험적 선택지로 안내합니다. [MVSep의 파트 정의](https://mvsep.com/en/algorithms?page=1).

Mega의 제작자는 전체 53개 출력을 처리하는 기본 실행에 **최소 16 GB VRAM**을 권장합니다. 앱은 공식 원본 가중치를 쓰면서 고정 실행 도구의 선택 출력 기능으로 `keys`·`synth` 두 출력만 계산·저장합니다. 중간 출력 메모리를 줄이는 방식이며 특정 GPU 용량에서의 성공을 보장하지 않습니다. Apple MPS에서도 선택 출력 경로가 유지되도록 이 모델만 Torch 백엔드를 사용합니다. 메모리 절약은 8초 문맥이며, GPU 메모리가 부족하면 CPU로 명시적으로 다시 실행할 수 있습니다.

Leap의 위 평가는 881,559샘플 문맥, overlap 2, batch 2, fp32, TTA 없음입니다. 앱은 같은 기본 문맥과 overlap을 쓰되 batch 1로 메모리 사용을 줄입니다. 메모리 절약의 8초 문맥은 별도 처리 설정이며 위 점수와 같은 결과라고 보장하지 않습니다. SW의 기본 문맥은 588,800샘플, overlap 2입니다. 서비스 전용 고성능 모델·앙상블의 숫자를 다운로드 가능한 모델의 성능으로 사용하지 않았습니다.

공식 저자 모델인 [anvuew FT1](https://huggingface.co/anvuew/BS-RoFormer)의 [Multisong 결과](https://mvsep.com/quality_checker/entry/10845)와 [becruily 기타 모델](https://huggingface.co/becruily/mel-band-roformer-guitar)도 확인했습니다. 각각 다른 음질·조건의 대안입니다. SAM Audio와 Banquet 같은 범용·질의 기반 분리 연구는 이번 고정 파트 모델과 평가·입출력·필요 자원이 달라 직접 교체하지 않았습니다. [SAM Audio 공식 구현](https://github.com/facebookresearch/sam-audio), [Banquet 논문](https://arxiv.org/abs/2406.18747).

## 15개 선택지를 만드는 방식

보컬·기타·드럼·베이스·키보드·피아노·신시사이저 각각에 **해당 파트만**과 **해당 파트 없이**를 제공하고 원곡을 더해 15개 선택지를 만듭니다. ‘없이’는 원곡 PCM에서 선택한 모델의 해당 파트 출력을 뺀 결과입니다. 다른 악기와 잔여 소리를 보존하며, 기타 반주를 만들 때 보컬까지 임의로 없애지 않습니다. 완벽히 제거되지 않거나 잔향·누출이 남을 수 있습니다. 서로 겹치는 키보드·피아노·신시사이저 출력을 합쳐 하나의 악기나 원곡으로 만들지 않습니다.

서로 다른 모델의 보컬과 악기 출력을 모두 합쳐 원곡으로 간주하지 않습니다. 원본에서 해당 파트를 뺀 결과와 단독 출력은 같은 기준·길이를 공유합니다. 모델 출력은 부동소수점으로 저장하고 각 악기를 따로 최대 음량에 맞추지 않습니다. `.magic`의 정수 PCM/MP3 저장 범위를 넘는 피크가 있으면 체크한 모든 음원에 **하나의 공통 감쇠**를 적용합니다. 그 값은 형식 4의 `audio_gain`으로 기록되고 재생기에서 다시 적용하지 않습니다. 손실 MP3 인코딩 자체의 오차까지 없애는 처리는 아닙니다.

## 캐시와 이전 버전

캐시 키는 원본 전체 SHA-256, 모델의 고정 파일·해시, 처리 설정과 파이프라인 버전을 포함합니다. GPU 장치는 제외하므로 같은 처리 설정의 검증된 결과를 CPU·CUDA·MPS에서 공유할 수 있습니다. 선택한 악기 이름은 비싼 모델 실행의 공통 키에서 분리합니다. SW로 기타를 만든 뒤 베이스를 선택해도 저장된 전체 파트를 읽어 결과를 만들며 모델을 다시 실행하지 않습니다.

새 파이프라인은 **3**입니다. 기존 HyperACE·deux 파이프라인 2의 정확한 서명과 출력 해시를 확인하는 별도 경로를 유지합니다. 예전 표시 이름과 새 모델 필드 때문에 캐시를 놓치지 않도록 옛 서명을 그대로 계산합니다. 새 파일의 길이는 44.1 kHz 원본 PCM 샘플 수에 맞춥니다. 기존 결과의 끝부분 차이가 0.1초 이내일 때만 새 복사본 끝을 보정하고 그 내역을 기록합니다. 기존 파일·시작 시각·보정한 악보 시간표는 바꾸지 않습니다.

자동 추천에서 새 모델을 선택하는 것은 다른 처리이므로 기존 모델의 결과를 그 모델의 결과라고 재사용하지 않습니다. **기존 캐시를 쓰려면 원래 모델과 메모리 설정을 선택하세요.** 캐시가 정상이라면 모델 다운로드·GPU 확인·추론 라이브러리 가져오기가 필요 없습니다.

PC의 `.magic` 캐시는 `processed/imported-magic/<실제 archive SHA-256>/v1/`에 둡니다. 파일 안에서 주장하는 원곡 해시로 기존 분리 캐시를 덮어쓰지 않습니다. 저장된 모든 음원·악보·시간표를 검증하고, 원본 PDF/GP는 분석하지 않고 보관합니다. 악보는 저장된 PNG를 표시합니다. 형식과 호환성은 [MAGIC_FORMAT.md](MAGIC_FORMAT.md)를 참고하세요.

## 실제 실행에서 확인한 범위

선정한 가중치를 실제로 내려받아 위 SHA-256을 검증했습니다. 별도 환경에서 고정한 **pymss 2.4.0 / pymss-core 0.1.16 / CPU PyTorch 2.14.1**로 앱의 실제 `engine.separate_stems()`를 실행했습니다. 의존성 검사가 통과했습니다. 이 앱의 기존 설치 의존성은 바꾸지 않았습니다.

검증 입력은 직접 만든 스테레오 합성 신호 **220,637프레임(약 5.003초), 44.1 kHz**입니다. SW 기본 문맥과 8초 문맥, Leap 기본 문맥에서 모든 예상 출력이 유한한 값·2채널·정확한 전체 길이로 생성되었습니다. Leap의 보컬과 반주를 더한 값의 원본 대비 최대 절대 오차는 약 **1.31×10⁻⁸**이었습니다. 이는 실행·파일 무결성 검증이며 실제 음악의 청감 품질이나 SDR 재현 검증은 아닙니다.

실제 CUDA·Apple MPS 메모리 사용량과 곡 전체 처리 시간은 이 검사로 측정하지 않았습니다. 메모리 절약도 입력 길이·창 분할에 따라 효과가 달라지므로 일정한 메모리 절감률이나 처리 속도를 약속하지 않습니다. macOS·Windows 설치/GUI 검사와 실제 GPU·스피커 검증은 구분합니다.

Mega도 공식 가중치·설정 해시를 검증한 뒤 같은 고정 실행 도구의 실제 `engine.separate_stems()`로 실행했습니다. 직접 만든 **529,337프레임(약 12.003초)** 스테레오 입력에서 기본 **20초 문맥·50% 겹침**과 **8초 문맥·50% 겹침**을 각각 사용했습니다. 두 실행 모두 `keys`와 `synth` 두 파일만 생성했으며, 모든 샘플이 유한하고 정확히 529,337프레임·44.1 kHz·2채널이었습니다. 8초 시험은 입력이 청크 경계를 넘습니다.

이 Linux CPU 환경의 모델 로딩·입출력 포함 실행 시간은 기본 약 **151.68초**, 8초 문맥 약 **160.39초**였고, 최대 프로세스 RSS는 각각 약 **4.94 GiB**, **4.14 GiB**였습니다. 짧은 합성 입력의 호환성 측정이며 전체 곡의 처리 속도·실제 음악 품질·사용자의 RTX 4070 Ti나 Mac 성능을 예측하는 수치가 아닙니다. GPU VRAM 사용량도 아닙니다.
