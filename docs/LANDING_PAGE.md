Combined audio is prepared from successive residuals on the computer, never by adding or subtracting overlapping complete listening versions in the browser. `저장된 음원 불러오기` verifies existing current-format cache entries, including completed combinations, without inference. ## Score and following descriptions

For v2.4.2, distinguish notation data from PDF display and geometry. A corresponding selected MusicXML file, or a valid MusicXML attachment embedded in the PDF, is preferred for notation analysis. Without it, PDF note recognition can be supplemented by supported printed navigation text and music-font glyphs. An arbitrary XML attachment is not necessarily MusicXML. Do not promise universal recognition of a publisher's scores, every font, or a scan.

Geometry/BPM timing is a limited fallback when notation is unavailable or recognition fails. It can find measure layouts in paired standard-notation/TAB PDFs and multi-staff scores; this does not split parts or transcribe TAB numerals into pitches. Invalid or conflicting navigation and a failed supplied MusicXML analysis must not be described as successful straight-through playback. Explain that users need to check repeat/coda routes, pickups, meter/tempo changes and the actual recording before relying on following. PNG/JPG/JPEG are not direct inputs, and image-based PDFs may fail recognition.

Describe the PDF MusicXML selector and audio/fixed-tempo timing choices using the shipped UI labels. v2.4.9 stacks PDF and GP pages vertically and centers the active measure in the score viewport, with space above and below the document so first/last measures can also center. Consecutive forward system/page transitions within one viewport height move smoothly; longer moves, seeks, repeats and coda jumps go directly to the intended location. Simultaneous staves are centered as one block, so tall full scores still need an appropriate user-selected zoom or page fit. Do not guarantee that the next page is always visible: preview depends on zoom, viewport height and the original page margins. Suggest lower zoom, desktop page fit or more vertical space when needed; preserve complete source pages. Manual movement suspends following; re-enabling `자동 넘김 · 스크롤` on desktop or `자동 따라가기` on web immediately centers the actual current measure, including when paused. Saved measure boxes adapt to zoom, resize and preparation-panel changes without reanalysis. Only missing legacy measure positions require `악보 사전 분석` → `기존 마디 시간표 유지 · 화면 이동 경로만 분석`; this preserves the existing timeline. Corrected timings require a new `.magic` export, but the centered-view change alone does not.

For v2.4.4, describe `마디 강조` as an optional display setting, on by default on both desktop and web. Each app/browser remembers its own choice. Turning it off hides only the colored measure overlay; following, measure numbers, playback and timing remain independent. Turning it back on uses the existing measure positions. Keep the landing explanation brief and leave the detailed controls in the user guides.
